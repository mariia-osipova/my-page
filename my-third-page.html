Flappy Fish: Genetic Algorithm Game

Mariia Osipova December 19, 2025

Flappy Fish is a group practical-assignment project built in Pygame by mariia-osipova, julietazanoni, and SantuCode11. At first it looks like a small arcade game: a fish swims through an underwater scene, obstacles move across the screen, and the goal is to survive by passing through openings without hitting the environment. The main point of the project is bigger than the game itself: the same game becomes a test environment for a genetic algorithm.

The idea

The project explores one question: can an agent learn when to flap if it only receives a few measurements from the current game state? To test that, the team built one modular game with two control modes. Manual mode lets a person play the game directly. Simulation mode replaces the player with many AI-controlled fish and lets them improve over repeated generations.

Manual mode

Manual mode is the baseline version of the game. A player controls one fish, tries to pass through gaps, and gets a score based on progress. This mode was useful because it made the core mechanics visible: gravity, flap strength, obstacle spacing, collision hitboxes, scoring, restart behavior, and the general feel of the controls all had to work before the learning system could be trusted.

Simulation mode

In simulation mode, the game creates a population of fish instead of one player-controlled fish. Each fish has its own set of numeric weights, which works like a genome. On every frame, the fish reads a small state vector: the vertical difference to the next gap, the horizontal distance to the next obstacle, and its current vertical velocity. Those values are combined by a policy that decides whether the fish should flap.

Genetic algorithm

Training happens in generations. During one generation, every fish attempts the same game environment and receives a fitness score based on performance, such as distance traveled, survival time, and progress through obstacles. When the generation ends, stronger fish are more likely to be selected as parents using fitness-proportionate, roulette-wheel-style selection. Their weights are mixed with crossover, then slightly changed through mutation, creating the next generation of fish.

What the simulation shows

The automatic mode is useful because it makes the learning process visible. The screen can show generation number, how many fish are still alive, the state values used by the policy, genome-weight statistics, and a fitness-progress chart. Instead of only seeing a final score, you can watch the population gradually discover better timing for flapping through the gaps.

Architecture

The project separates the game responsibilities from the algorithm responsibilities. The game loop, fish physics, collisions, obstacle generation, screens, and visual assets are kept apart from the genetic-algorithm logic. That separation is important because the same environment has to work with two different controllers: human input in manual mode and autonomous decisions in simulation mode. The deployed web version adds another layer around the original game, including score and leaderboard behavior.

What I worked on

My part focused on implementation, algorithm and game integration, documentation, and deployment polish. In the repo, my commits include finishing the Fish and Game modules, tuning fish physics and collision behavior, building the genetic-algorithm simulation with generations, weights, genes, and a 100-fish population, adding simulation UI details, improving screenshots and README material, adapting the web demo, and connecting score and leaderboard sync through Google Sheets and a server proxy.

Why it was useful

This project made the genetic algorithm concrete. Small changes to fitness scoring, mutation, selection pressure, physics, or collision rules immediately changed what happened on screen. That made it a good systems project: the algorithm only worked when the game loop, state representation, scoring, UI, and deployment details all lined up.
